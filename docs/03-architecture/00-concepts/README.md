# Layer 00 — Concepts

Home of `CON` documents: precise, cross-cutting definitions of ideas that appear in **multiple layers or contexts** and must mean exactly one thing — e.g. *Tenant*, *Quality-Based Payment*, *Consent*, *Dispute* (one of the four shared patterns from [QR-0002 §4](../../12-quality/QR-0002-gap-analysis.md)).

## What Is (and Is Not) a Concept Document

- **Is:** the single authoritative definition of an idea, its distinctions from neighbors, and how it manifests in each layer that uses it.
- **Is not:** a glossary entry (one paragraph — concepts too small for a CON stay in the [glossary](../../11-glossary/GLOSSARY.md)); not a domain model (context-bound modeling belongs to `DOM`); not a policy (rules with enforcement belong to `POL`).
- **Threshold:** create a CON when two or more contexts/layers would otherwise each define the idea themselves. The glossary entry then points to the CON.

## Rules

- Template: [TPL-0013](../../02-templates/TPL-0013-concept-template.md). Naming: `CON-NNNN-<concept-name>.md`.
- Every CON term exists in the glossary; the glossary links the CON as its source.
- Approval: Architecture Board member + owners of the consuming contexts ([GOV-0002](../../01-governance/GOV-0002-approval-workflow.md)).
