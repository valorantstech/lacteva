# Software Requirements (SRS)

Software Requirements Specifications define **precise, testable system behavior**: functional requirements with error paths, quantified non-functional requirements (performance, scalability, availability, security, multi-tenancy, data residency, observability), interfaces, and a traceability matrix. QA derives test plans from the SRS.

- Template: [TPL-0004](../../02-templates/TPL-0004-software-requirements-template.md)
- Naming: `SRS-NNNN-<short-title>.md` per [STD-0002](../../00-standards/STD-0002-naming-conventions.md)
- Approval: owning engineering lead + product manager ([GOV-0002](../../01-governance/GOV-0002-approval-workflow.md))
- Scope: one SRS per service or coherent system; platform-wide requirements (e.g. tenancy) live in a platform SRS that service SRSs reference instead of restating.
